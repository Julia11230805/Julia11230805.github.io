# re:poem — 文字的第二次生命

以余秀华诗歌中的主题、意象与情感为灵感的互动式数字诗歌实验。
原生 HTML5 / CSS3 / JavaScript，无框架、无构建、无后端。

---

## 运行（推荐：本地服务器）

双击桌面上的 **`re-poem 网站.bat`** ——它会用系统 Python 起一个本地服务器、
自动打开浏览器，然后在这个窗口里挂着网站。关掉窗口网站就停。

| 地址 | 谁可以打开 |
| --- | --- |
| http://127.0.0.1:8123/ | 本机任意浏览器 |
| http://192.168.5.20:8123/ | 同一个 Wi-Fi 下的手机、平板（IP 随路由器变，以 `ipconfig` 为准） |

也可以直接双击 `index.html`（file:// 模式），全部功能可用；只有两处差别：
`navigator.clipboard` 在 file:// 下不可用会退回 `execCommand`，以及部分浏览器
对 file:// 的 localStorage 更严格。

### 浏览器兼容（实测，非推测）

用 Playwright 跑 Blink / Gecko / WebKit 三套内核 × 桌面 1440×1000 + 手机 390×844 × 五个页面，
共 **33 项检查，0 个失败**，控制台零报错，点击流程（封面视频播放 → start → 翻页书 → next → 素材库）三内核全部通过。

已修掉的兼容点：

| 问题 | 修法 |
| --- | --- |
| `background-attachment: fixed` 在 iOS Safari 失效 | 改成固定定位的 `::before` 图层 |
| `backdrop-filter` 在 Safari 不生效 | 补 `-webkit-backdrop-filter` |
| `offset-path: path()` 老内核不认，针僵在角上 | `@supports not (…)` 时隐藏那根走针 |
| `contenteditable="plaintext-only"` 老内核不支持 | `isContentEditable` 为假时退回 `"true"` |
| `100dvh` 老内核不认 | 先写 `100vh` 兜底 |

渲染一致性（逐像素比对同尺寸截图）：海报页 Chromium↔WebKit 平均差 **1.02 灰阶**、
↔Firefox **1.44**；布面毛边（SVG 位移滤镜）在三个内核的起伏都是 **9–10px**，WebKit 没有丢。

## 直接双击运行

直接双击 `index.html` 即可。不需要装任何东西，也不需要起服务器。

（`js/` 里用的是经典脚本 + 一个极小的模块注册表，而不是 ES Modules——
ES Modules 在 `file://` 协议下会被 CORS 拦住，双击打不开。所以模块化是靠
`RePoem.module()` 注册、`RePoem.use()` 取用，每个文件仍然只负责一件事。）

## 设计规范（模块 01 建立，后续模块沿用）

颜色不是编的，是从那张插画里取的：

| 令牌 | 值 | 来源 |
|---|---|---|
| `--paper` | `#FBF0F0` | 画纸（rgb 251 240 240） |
| `--wine` | `#4C1B2F` | 插画墨色的中位数 |
| `--wine-deep` | `#2C0C1B` | 最深的笔触 |
| `--wine-lift` | `#7E2A42` | 交互时的提亮 |
| `--wine-wash` | `#886878` | 稀释后的晕染 |

字体（全部为系统字体，不联网、不阻塞首屏）：

| 用途 | 字族 | 说明 |
|---|---|---|
| 英文标识 / 进入提示 | `Segoe Script → Brush Script MT → Gabriola` | 手写卷曲体 |
| 中文标题 | `华文行楷 → 方正舒体 → 楷体` | 行书笔意，有连笔与回锋 |
| 正文/备用 | `Palatino Linotype → Constantia → Georgia` | 备用衬线 |

卷曲类字体自带节奏，字距必须接近 0（`0.02em`）；一旦拉到 0.2em 以上，
手写体会被拆成一个个孤立的字母，看起来像打字机。中文相反，留 0.14em 的
字距才像排过版。

## 封面这一页的三条硬规矩

1. **不碰视频**。视频元素上没有任何 `filter`、`opacity`、`transform`，
   `object-fit: cover` 固定，所以画面永远不会被拉伸或重采样。
2. **文字落在画的留白里，而不是浏览器窗口的某个位置**。
   `stage.js` 实时量出视频在 cover 模式下真正占据的矩形（`videoWidth/Height`
   与 `clientWidth/Height` 推算），把 `.stage` 铺成同样大小；文字按这个矩形的
   百分比定位，所以窗口怎么变，字都在原画的同一处。
   实测落点：原画 y≈163（`re:poem`）与 y≈188（`click to start`），
   该区域墨迹密度 0.000%——完全空白。
3. **`object-position: 50% 18%`**。近方形的画放在宽屏上，cover 会裁掉上下各一大截；
   往上偏 18% 是为了让"额头正上方那条留白"始终留在视口内，字不会被裁掉。

### 底图：一只眼睛的油画

选词界面的背景是另一张画（`assets/img/lib-bg.jpg`，1206×1178，正方形）。
它不铺在书页上，只铺在这一页，两层：

```css
body.is-library::before {          /* 画本身，固定铺满视口 */
  position: fixed; inset: 0; z-index: -2;
  background: url(../assets/img/lib-bg-web.jpg) center top / cover no-repeat;
  opacity: var(--bg-ink);          /* 桌面 0.72，手机 0.50 */
  transform: scaleX(-1);
}
body.is-library::after {           /* 纸色渐隐：左边压字区重，右边让画出来 */
  position: fixed; inset: 0; z-index: -1;
  background: linear-gradient(96deg, rgba(251,240,240,.6) 0%, … 0.02 100%);
}
```

**为什么要镜像**：原画的眼睛在左上，正方图铺到 1440 宽的页面上，眼睛正好落在
标题和说明文字底下——压重了看不见，压轻了抢字。`scaleX(-1)` 之后眼睛到右侧
（标题旁边那块空白），文字区干净。原图文件没有改动，不要镜像就删掉那行 transform。

**注意 `transform` 会连背景定位一起镜像**：手机端要取画的右侧，写的是
`background-position: 0%`，不是 100%。

文字对比度实测（只拍背景、藏起文字）：标题区最暗 1% 分位亮度 190，
墨色 `#4C1B2F` → **7.54:1**，小字 `#4A2536` → **7.06:1**，都远过 AA。

### 纸片是怎么做出来的

每个词是一张独立的手裁纸，不是一个按钮。三层叠加：

1. **纸层**在 `::before`（绝对定位、`z-index:-1`、`isolation:isolate` 关住层级），
   所以文字在按钮本体上，永远清晰；
2. **毛边**用 SVG 位移滤镜 `feTurbulence + feDisplacementMap`（`baseFrequency 0.085/0.11`、
   `numOctaves 5`、`scale 7`）只作用在纸层上——文字不受影响，这是关键；
   `0 0 0 1px` 的浅色 box-shadow 被同一个滤镜推成锯齿，就是撕纸的白色纤维边；
3. **每片不同**：`--paper` 四色纸、`--rot` ±3.1°、`--dy` ±1.8px、`--jx/--jy` 内边距抖动，
   全部由词的 hash 决定——同一页刷新多少次，纸片都不会跳位。

纤维只画一个方向（`repeating-linear-gradient` 92deg）；早先画了两个方向交叉，
看起来像网格线而不是纸。

### 交接

- 模块 02 点 `next` 时把诗的基调写进 `sessionStorage['repoem:mood']`
  （`{poem:'唯独我，不是', tags:['孤绝','疼','渴望']}`），模块 03 据此推荐 14 个词；
- 点「进入拼贴工作台」把 `{words, mood, at}` 写进 `localStorage['repoem:handoff']`，
  然后跳到 `collage.html`（模块 04 的占位页，目前只把收到的词摊在桌上，证明交接通了）；
- 已选词和自定义词各自持久化（`repoem:selected` / `repoem:custom`），刷新不丢。

### 实测

- 五个分类切换、搜索（跨分类，命中词带分类小标）、自定义添加（按钮 + 回车）、
  框内点选、底部标签取消、数量同步（`已选 N` 与按钮 `· N`）、刷新后保持——
  逐项在 Chromium 里跑过；
- 手机 390×844：无横向溢出，纸片 64×45px（≥44 触控线），分类栏单行横向滚动，
  最后一排纸片滚到底时完整露在固定栏之上（`lastBottom 587 < barTop 723`）。

### 两个踩过的坑

- `RePoem.module(name, fn)` 是**注册即执行**，`fn` 的返回值就是模块 api；
  写成 `return { init() {...} }` 那个 `init` 永远不会被调用（页面会整片空白）。
- `base.css` 里 `html, body { height: 100% }` 会把 `padding-bottom` 吃进去，
  固定底栏就会压住最后一行；`body.is-library { height: auto }` 才能让页面按内容长高。

## 模块 04 · 诗歌生成（collage.html）

标题「让碎片成为诗」。读模块 03 的 `repoem:handoff`（词 + 基调），出诗。

**版面是一张刺绣小工具的画法**（参考了一件小红书上的刺绣程序）：粉麻布做底，
诗写在一块白棉布补丁上，四周一圈蓝色绣线，布边是毛的，右上角一根针带着绿线
从布上穿出来，控制栏是布上方的一排工具。

- **麻布底**：四组 `repeating-linear-gradient`（经线两层、纬线两层，周期故意不等，
  再加两条歪斜的深色粗线当麻结）。等周期会读成"格子纸"，不等才像麻。
- **布补丁的毛边**：布面在 `.cloth::before` 上，只给这一层加
  `filter: url(#clothEdge)`（`feTurbulence` + `feDisplacementMap`，scale 13）；
  文字在元素本体上，永远清晰。**投影也必须放进同一层**，否则会出现"直影子配毛边"。
- **绣线框**：`inset: 18px` 的 `1.5px dashed`，虚线段就是针脚；四角原来还画了
  × 形交叉针，被误读成"关闭按钮"，删掉了。
- **工具在布的上方**，不是右侧栏 —— 布很高，右侧栏会被挤到首屏外面（实测过）。

### 刺绣动效（2.4 秒，每次生成都重播）

| 时间 | 发生什么 |
|---|---|
| 0.10s | 针从布的左上角起针，沿布边走一圈，**蓝绣线跟着它一针一针出现** |
| 0.32s | 诗题按 `steps(12)` 逐针擦出来 |
| 0.76s 起 | 诗行逐行出现，每行间隔 82ms，行内也是 `steps(13)` 的断续擦除 |
| 1.70s | 缝完，布角那根大针淡入（像刚缝完搁在那儿） |
| 1.82s | 右下角出处说明出现 |

三个技术点：

1. **绣线是"遮罩拉满"**，不是 `border-style: dashed` —— CSS 虚线框没法做逐段出现。
   `#stitchRect` 是那条虚线，被 `mask="url(#sewMask)"` 遮住；遮罩里的
   `#stitchMask` 用 `pathLength="100"` + `stroke-dasharray="100 100"`，把
   `stroke-dashoffset` 从 100 收到 0，就是沿周长从头缝到尾。
2. **遮罩里的元素没有布局盒，CSS 动画不会启动** —— 实测 `getAnimations()` 返回 0。
   这一段改用 SMIL：`<animate attributeName="stroke-dashoffset" begin="indefinite">`，
   由 `beginElement()` 在每次生成时重播。针和文字那两段用 CSS 就正常。
3. **针走的是 `offset-path: path(...)`**，路径由 JS 按布的实际尺寸算出来（`--sew-path`），
   `offset-rotate: auto` 让针尖永远朝前进方向。这块布是毛边的 SVG 滤镜做的，
   尺寸会变，所以窗口 resize 时要重算一次路径。

### 三种排法

| 模式 | 做法 | 可验证的性质 |
|---|---|---|
| 自由拼贴 | **每张字片都能拖**：把它拖到布上摆位置，同一行的字按从左到右连成一行诗 | 实时预览"现在是这样 N 行"，存下/交接用的就是这份文字 |
| 诗意重组 | 按词性出句，情绪与物象交替，句型不重复 | 33 个句型内一首最多用一次；每个词至少出现一次 |
| 随机生成 | 洗牌后随机套句型 | 每次换一版都不同（种子不同） |

### 语料

`js/data/templates.js`：33 个按词性填空的句型、12 个位次句型、14 个标题式，
外加 `PLACES`（地点）、`TIMES`（时间）、`INTRANS`（不及物动作）三张词表。
`make.js` 用这三张表决定"这个词该放在句子的哪个位置"，而不是随便塞。

### 为了不露机器味，做了四件事

1. **同一行不复用同一个词。** 最初按"槽位类别"去重，结果 `{t}`（时间）没词时会
   退回名词池，出现过"月光之后，孤独长成了月光"——现在按实际的词去重。
2. **同一句型一首只用一次**（随机的放宽到两次），并且最近六行内用过的句型不会再选。
3. **动词分及物不及物。** `我在___` 这种句型只放不及物的（`我在摇晃` ✓，
   `我在撕碎` ✗）；池子里一个不及物都没有时，这类句型整条被排除，换别的说法。
4. **物作主语的动作句改成"我"作主语。** `拐杖在抱膝` 这种是硬伤，
   原始句型已改成 `我在抱膝` / `谁在田埂边上抱膝`。

### 自由拼贴：拖字成诗

`js/modules/make.js` 里的 `buildClipboard` / `bindClipboard` / `linesFromLayout`：

- 每个词一张 `.slip`，用 `left: calc(var(--x) * 100%)` + `top: calc(var(--y) * 100%)`
  定位，坐标是**比例**，所以布面大小变了、位置也不会错；
- 拖动用 `pointerdown/move/up` + `setPointerCapture`，`touch-action: none` 防止手机上
  拖到一半页面跟着滚；键盘方向键也能挪（Shift 走大步）；
- 松手先 `snapToRow()` 吸附到行线，再 `resolveOverlap()`：**两张字片叠在一起，
  下面那张就"消失"了**，所以落点重叠超过 35% 就横向推开、推到头就换下一行；
- `linesFromLayout()`：按 y 排序，纵向中心差 < 7.5% 的算同一行，行内按 x 排序，
  用全角空格连起来——这就是这首诗；
- 布上还给了一行"重新摊开"（`resetLayout`）把所有字片放回初始分布。

### 标题：可以自己写

标题是 `contenteditable="plaintext-only"`，点一下就能改，下面常驻一条 1px 的线当暗示。
改过之后 `state.customTitle = true`，**"换一版"和切模式都不会把手写的标题盖掉**；
清空则自动补一个。手写的标题存在 `repoem:title`，刷新也还在。

### 编辑、保存、交接

- 「自己改几句」把诗稿切成 `contenteditable`，`innerText` 按行收回（不是 innerHTML，
  粘贴进来的标签不会带进数据）；
- 「存下这一版」写进 `repoem:poems`（题、行、模式、时间），右侧列出所有版本，
  点标题可载回，点 ✕ 删除；
- 「设计我的诗歌」把 `{title, lines, mode, words}` 写进 `repoem:chosen-poem`，
  跳到 `design.html`（模块 05，把诗排成海报）。

### 模块 04 的绣线要跟着布走

布边那条蓝色绣线（`.stitch` 里的 `#stitchRect` / `#stitchMask`）和针的路径
（`--sew-path`）都是 JS 量布的尺寸再画的。**切到「自由拼贴」时拼贴板出现，
布的高度会变，但以前没人重算**——实测布 720×679、绣线还停在 684×402，
底边差 259px，看起来就是「版面和刺绣动画没对齐」。

修法：`scheduleSync()`（60ms 防抖）作为唯一入口，三处触发——
`renderRail()` 切模式后、`window resize`、以及 **`ResizeObserver(el.cloth)`**。
最后这个是兜底，布因为任何原因变高变矮都会重算。修后实测：
诗稿模式 684×719 / 720×755，自由拼贴 684×643 / 720×679，
反复切换四边留白恒为 18px。

还有一层：自由拼贴的布比一屏高，**底部会压在固定底栏后面**，滚到顶上看就是
"绣线没包到底"。所以 `revealClothBottom()` 在切进自由拼贴时把布底滚进来
（只滚需要的那一段）。实测进模式后 scrollY 0 → 63，绣线底边 892 < 底栏 931，
`elementFromPoint` 打在布上而不是底栏。

### 这个模块踩过的坑

0. **海报比例不能写死 4:3。** 用户要求「背景图维持原本比例」，做法是宽固定 900、高 `900 × 图高/图宽`（`applyBg()` 里用 `new Image()` 量 `naturalWidth/Height`），布局、屏幕预览、导出 PNG 全用这一个 H。`background-size: cover` 配完全一致的宽高比就等价于整幅铺满，不裁也不留边。验证方式：导出 PNG 缩回原图尺寸后四角逐像素比对，平均差 1.4–1.7 灰阶（只剩重采样噪声），角点像素完全相同。
1. **file:// 下 canvas 会被本地图片污染。** 把 `assets/img/poster/bg1.jpg` 画进 canvas 再 `toDataURL()` 会抛 SecurityError（Chrome 把每个本地文件当独立源）。解法是把七张底图全转成 base64 存进 `js/data/bgs.js`，CSS 预览和 canvas 导出用同一份数据，顺带保证导出图 = 屏幕所见。
2. **`transform: scale()` 之后不能再乘一次 scale。** 海报是固定 900 宽的版面（高度随底图变），整体用 transform 缩放；纸条字号必须保持版面原值，否则字被放大两次，撑破纸条。
3. **`transform-origin: left top` 时视觉左上角 = 布局左上角。** holder 宽度就该等于 `900 × scale`，`left/top` 一律 0；之前写 `(W*scale - W)/2` 会整体偏移 30px。
4. **海报高度不能按「视口 × 0.72」拍脑袋。** 海报下面还有提示行和固定底栏，要用 `视口高度 - 海报起点 - 96` 真正剩下的空间，否则手机和矮屏上最后两行诗会被底栏吃掉。
5. **`::before` 的 `z-index: -1` 会被父元素自己的 background 盖住。** 纸条的纸层长在 `::before` 上（毛边滤镜只作用于纸层，文字保持清晰），所以 `.strip` 必须 `background: none`；诗题的暖色也改成写在 `.strip--title::before` 里。
6. **`filter: url(#id)` 需要滤镜定义在同一个文档里。** design.html 顶部那几行 `<svg><defs>` 不能省，删掉纸条和印章会直接变回硬边色块。
7. **`<a download>` 塞 3MB 的 data URL 会被静默丢掉**（页面毫无反应，控制台也不报错）。改成 `canvas.toBlob()` + `URL.createObjectURL()`。
8. **手机端不能照搬「左边控制、右边预览」。** 一屏装不下，海报会被挤到底栏下面；`@media (max-width: 900px)` 里把 `.stage { order: -1 }` 让成品先出来，控制栏在下。
